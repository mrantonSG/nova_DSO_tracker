# Nova DSO Tracker v7.2.1

**Release Date:** 2026-11-14

## Fix: synced journal sessions keep their integration time

Journal sessions that arrived through Instance Sync lost their total integration time. The value is derived from the session's subs, exposure and filter data, but the sync apply path wrote the synced columns without recomputing it — so a synced session showed no integration minutes until it was edited and re-saved.

- **Synced sessions are recomputed on arrival** — when a journal session is written during a sync, Nova now recomputes its integration time from the synced columns in the same write, so it lands with the correct total.
- **Existing instances self-heal on start** — installs that already pulled sessions before this fix have those rows stuck at NULL. On the next start Nova fills them in automatically (NULL rows only, idempotent), so no manual repair is needed.
- **Manual repair command** — a `backfill-integration` CLI command recomputes the column for every NULL session (dry-run by default; pass `--apply` to write). It leaves the sync change stamps untouched, so running it does not mark anything as changed to sync.

## Object switcher

- **The object switcher is now in the header** — the Switch Object modal moves out of the journal page into a shared partial, so it is available on every page. A new header icon (between Dashboard and Solar System) opens it pre-filtered to "In Planning", and choosing an object jumps to its journal page.
- **Sort and status are remembered** — the switcher's sort order and status filter persist across opens, and it can be opened programmatically with an explicit sort/status.
- **"In Planning" no longer hides multi-project objects** — an object with both a completed project (with sessions) and a planning project used to vanish from the In Planning filter, because the switcher collapsed to one status per object. Now every project status on an object is listed, so it shows up under each filter that applies.

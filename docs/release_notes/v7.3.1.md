# Nova DSO Tracker v7.3.1

**Release Date:** 2026-11-24

## Fix: Transit always shows the upper culmination

Nova used to report whichever meridian crossing fell between astronomical dusk and dawn. When an object's upper transit was in daylight, Nova showed its **lower** culmination instead. For example, M106 from New York on 2026-11-22 showed 20:08 at about -2° instead of 08:06 at 84°.

- **Transit is now always the upper culmination** - it is the high crossing in the local noon-to-noon window, even when that falls in daylight. This applies to the dashboard Transit column, the meridian-flip line on the graph, the mobile view and the facts Ask Nova is given.
- **Objects that never rise show "N/A"** - an object that never clears the horizon from your location no longer gets a transit time.
- **One transit time, one line** - the old "HH:MM, HH:MM" double value is gone. The graph draws a single transit line.
- **Ask Nova uses the right night** - when the transit falls after midnight, the Moon separation is now worked out for the correct calendar day.

## Fix: Dashboard header shows today's date

After midnight, the dashboard and Solar System headers still showed the date the observing night began. They now show the calendar date at your location. Everything that belongs to a night (sun events, Moon, observable time, Ask Nova) still uses the observing night, as before. In simulation mode the header shows the simulated date, as before.

## Graph

- **The "Now" label stays on top** - a Sunrise or other sun-event label close to the current time no longer covers it.
- **Labels follow the theme** - the Now and transit labels used a white background, even in dark mode. They now use the same themed chip as the sun-event labels and keep their red text.

## For self-hosters

- **New optional setting `NOVA_DISABLE_UPDATE_CHECK`** - set it to `1` in `instance/.env` (or `docker run -e NOVA_DISABLE_UPDATE_CHECK=1 ...`) to turn off the daily GitHub release check. Nova then makes no request to GitHub and shows no "Latest version" notice in the header. Only the exact value `1` turns the check off. If it is unset, nothing changes. Restart Nova after changing it. See the README's **Update Check** section.
- **API changes:**
  - Transit values (dashboard data, `/m` and the object API routes) are now always a single `HH:MM` or `N/A`. Clients that parse the old comma-separated pair should expect one value.
  - `/sun_events` has a new `local_date` field, the location's calendar date. `date` is unchanged and is still the observing night.
  - When the update check is turned off, `/api/latest_version` returns `{}`, the same answer as "no update available".
- **No database changes** in this release, and **no new Python dependencies**.
- **Back up your `instance` folder before you upgrade.**

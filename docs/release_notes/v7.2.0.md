# Nova DSO Tracker v7.2.0

**Release Date:** 2026-11-13

## New: Instance Sync — bring Nova offline and sync back

A new page, opened from the Configuration page, lets two Nova instances keep each other up to date. One instance acts as the **server** — the hosted nova-tracker server, or an instance of your own — and the other connects to it as a **client**.

- **Server and client** - the server mints a sync token for each client instance (Nova stores only a hash of it, so it is shown once and never again). On the client you enter the server's address and the token, and the two are paired.
- **Download from the server** - the first thing a freshly connected instance does is pull the server's data down. It is a full replace, so Nova takes a backup first and asks you to type REPLACE before it touches anything.
- **Sync now** - after that first download, sync runs in both directions. A summary appears before anything is applied: what will go up and what will come down, counted as new, changed and deleted, and the files to transfer with their sizes.
- **Files travel too** - session photos, note images, the ASIAIR / PHD2 / NINA logs and project images are all part of a sync. A record whose photo or log was replaced keeps its name, so the new bytes are detected by their content and moved across.
- **Changed on both sides** - when the same record was edited on two machines since they last talked, Nova shows the conflict lines and the newest change wins, on both sides.
- **Deletes are deliberate** - a sync that would delete a large number of records asks you to confirm, once per direction, and a full replace asks you to type REPLACE. Files displaced by an incoming version are moved aside under `instance/replaced/`, never deleted, so a bad merge is recoverable.
- **Offline workflow** - image without any internet connection. Sessions, objects, logs and photos are recorded as usual, and the next "Sync now" once you are back online brings the two instances together.

## Things that look different

- **The header now has a single icon model** - Dashboard, Solar System and Configuration appear as icons on every page, with the page you are on highlighted instead of disappearing. Info and the theme toggle sit in their own group, and the per-page "Back to Dashboard" and Configuration text buttons are gone in favour of the always-present Dashboard icon. The icon buttons now share one style with a consistent size, focus ring and active state.

## Fixes

- **Empty log uploads are rejected** - a zero-byte or whitespace-only ASIAIR, PHD2 or NINA log used to be handled inconsistently (some were saved, some dropped). Now both the add and edit forms refuse them and leave any already-attached log untouched.
- **Path containment hardened** - the ZIP journal-photo import and the editor image upload now resolve every path through a single containment check that refuses `..`, absolute parts and symlink escapes, closing a path-injection vector. An error message that could leak an internal path is replaced with a translated generic one.
- **Skyglow stays quiet when background tasks are off** - instances with `NOVA_DISABLE_BACKGROUND_TASKS=1` no longer make skyglow requests.

## For self-hosters

- **This release does change the database.** On first start `_run_schema_patches` adds two columns (`sync_changed_at`, `sync_rev`) to the ten synced tables (locations, objects, components, rigs, journal sessions, projects, saved views, saved framings, custom filters and UI prefs), creates the four sync tables (`sync_counter`, `sync_tombstones`, `sync_state`, `sync_tokens`), and runs one `sync_v1` backfill that stamps every existing row so pre-upgrade data is distinguishable from changes made after. It also adds a `last_seen` column to `DbUser` for aggregate active-user counts. All of it is automatic and idempotent; back up your `instance` folder first.
- **New blueprints:** `sync` (the `/sync` token page — create, revoke, connect, download, sync, confirm, abort, held records, job polling) and `sync_api` (nine token-scoped, session-free POST endpoints under `/api/sync/v1/*`: `hello`, `changes`, `snapshot`, `file`, `push/plan`, `push/file`, `push/apply`, `push/cancel`, `repair`). The sync API is outside the Flask-Login gate, so it neither provisions nor counts a guest.
- **New modules:** `nova/sync_engine.py` (merge engine and file transfer), `nova/sync_job.py`, `nova/sync_client.py`, `nova/sync_tracking.py` (change tracking), `nova/sync_transport.py` (hub transport) and `nova/sync_time.py`.
- **New on-disk directories:** `instance/sync_staging/` (staged files and owed placements), `instance/sync_uploads/` (chunked push accumulator), `instance/replaced/<user>/` (displaced files) and `instance/backups/sync/<user>/` (pre-push snapshots, newest five kept).
- **New environment variables:**
  - `NOVA_SYNC_CLIENT` — whether this installation may connect *outward* as a client. Empty (default) means on in single-user mode and off in multi-user mode; `on` forces it on, `off` forces it off, anything else (typos included) is treated as empty. A multi-user instance normally serves sync and mints tokens while this stays off; only enable it there on a trusted, private instance.
  - `NOVA_TELEMETRY_CHANNEL` — deployment channel tag sent with telemetry pings and skyglow requests (`prod` by default).
- **File size caps per sync role:** session photos 5 MB, logs 10 MB, note images 10 MB, project images 50 MB. The sync JSON body is capped at 16 MB.
- **Analytics** - the in-app `/analytics` page is removed (it is replaced by Grafana). Telemetry gains a central collector endpoint with a single-sender lock, and the `/analytics.json` aggregate endpoint now reports daily active-user counts from `users.last_seen`.
- **Back up your `instance` folder before you upgrade.**
